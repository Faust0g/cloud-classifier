# Particiones de datos congeladas

Para el manifiesto inicial se particionan CCSN, Open Images V7 validation y sociedad; las fotos propias y el set identificado como trampas quedan fuera. Los grupos de parecido son componentes conexos por autor conocido o pHash64 con distancia de Hamming ≤ 8; CCSN no aporta metadatos de autor y por eso se agrupa solo por pHash, un control de fuga más débil. Los nombres de autores no se versionan: Open Images usa IDs estables `autor_NNN` y la tabla nombre→ID queda bajo `data/`; la sociedad usa `desconocido` por imagen. Los nombres para atribución permanecen en `docs/datasets/`.

El manifiesto versionado es `manifests/partitions-v1.json`; cada fila contiene exclusivamente `path` (relativa a la raíz), `class_id`, `source`, `author_id`, `phash64` y `split`. Los valores de autor son IDs opacos `autor_NNN` o `desconocido`; no se incluyen nombres, IDs de imagen o grupo, semilla, conteos ni metadatos adicionales. La semilla y las decisiones metodológicas se registran en este ADR; el detalle de distribución queda en el informe local.

La asignación apunta a 70/15/15 por clase, equilibrando también fuentes de forma aproximada, sin descartar ni dividir grupos. La semilla inicial fija es `42`. El parámetro inmutable `LARGE_GROUP_EVAL_TARGET_FRACTION = 1/3` define grupo grande como un grupo cuya cantidad para alguna clase supera un tercio del objetivo de calibración o prueba de esa clase (cada objetivo equivale al 15% del total de la clase); los grupos grandes se asignan enteros a entrenamiento. Para evitar concentrar grupos de varias imágenes en evaluación, los grupos restantes se estratifican por tamaño exacto y composición de fuente; cada estrato recibe cuotas de cantidad de grupos 70/15/15 mediante restos mayores. Dentro de esas cuotas se asignan grupos para reducir el desbalance por clase; el orden y los empates usan la semilla fija. El informe expone proporciones reales, distribución de tamaños de grupo y muestras escasas sin corregirlas automáticamente.

En la partición congelada, `cirrus` tiene 24 imágenes en calibración, menos que el mínimo de 30 usado como referencia para muestras por clase. Por ello, #11 debe reportar el soporte y la incertidumbre de las métricas por clase, evitando presentar estimaciones de clases con pocas imágenes como concluyentes.

El pHash se calcula tras aplicar orientación EXIF, convertir a escala de grises y redimensionar a 32×32 con Lanczos. Se calcula la DCT bidimensional, se toman sus coeficientes de baja frecuencia 8×8 y cada uno de los 64 bits indica si su coeficiente es igual o mayor que la mediana de esos 64 coeficientes.

El informe y el manifiesto candidato se revisan antes de congelar; el manifiesto versionado se publica solo después de aprobación humana explícita del informe y no se sobrescribe al extender. Las asignaciones congeladas se conservan al extender. Las trampas futuras no se asignan automáticamente: antes de cualquier asignación, se comparan por pHash64 con todas las imágenes congeladas usando Hamming ≤ 8; cualquier coincidencia se informa y requiere consulta/aprobación humana antes de continuar. El inventario, las tablas de equivalencia de autores y los archivos de imagen permanecen bajo `data/`, ignorado por Git salvo `.gitkeep`.
