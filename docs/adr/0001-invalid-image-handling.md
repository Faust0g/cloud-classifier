# Manejo de imágenes inválidas

Para rechazar imágenes inválidas sin forzar un género de nube, el clasificador tendrá una clase adicional `no_nube`, y la aceptación de una predicción estará además condicionada por un umbral de confianza calibrado con datos de validación. La eficacia del rechazo se evaluará con un set de trampas separado del entrenamiento y la validación, sin usarlo para ajustar el umbral.

CCSN y el subconjunto `no_nube` de Open Images se dividirán en tres grupos disjuntos: entrenamiento (70%), calibración del umbral (15%) y prueba (15%, set de trampas). Las imágenes se agruparán combinando las señales de autor y de casi-duplicado: imágenes del mismo autor o enlazadas por similitud de hash perceptual pertenecerán al mismo grupo y no podrán separarse entre conjuntos. Se usará un hash perceptual de 64 bits; una distancia de Hamming de hasta 8 bits inclusive identifica casi-duplicados. Las fotos propias de cielo despejado podrán aportar ejemplos `no_nube` y se agruparán por sesión de captura; las fotos propias etiquetadas como nubes quedarán solo en la prueba final. Las fotos propias permanecerán fuera de Git; el manifiesto versionado usará IDs opacos y no contendrá nombres personales ni metadatos EXIF. Se usará una semilla fija para repartir los grupos, estratificando por clase y apuntando a las proporciones 70/15/15 donde la disponibilidad lo permita. Un manifiesto de partición versionado registrará la asignación, la semilla y el resumen de proporciones y conteos por clase. Una prueba automatizada verificará que no se repitan IDs ni grupos entre conjuntos. La partición de prueba no se usará para entrenar ni calibrar.

El umbral se elegirá en calibración maximizando la cobertura de predicciones aceptadas, sujeto a una precisión mínima del 95% entre ellas. La evaluación informará macro-F1, precisión y recall por clase, matriz de confusión, cobertura y tasa de rechazo del set de trampas.

Para las clases de nubes se usará como fuente el dataset Cirrus Cumulus Stratus Nimbus (CCSN), publicado en Harvard Dataverse bajo CC0 1.0. La licencia permite subir sus imágenes y publicar modelos derivados sin la advertencia operativa aplicable a Open Images. Las estelas (`Ct`) de CCSN se mapearán a `no_nube`; esta decisión es revisable si perjudica la clasificación de cirrus. Para `no_nube` se mantiene un subconjunto acotado de Open Images V7, descargado mediante un script que por defecto usa `validation` (unas 41.000 imágenes) en lugar de recorrer el split `train` de unos 9 millones de imágenes. El script selecciona imágenes con etiquetas positivas verificadas por humanos y excluye las que tengan etiquetas positivas verificadas para `Sky`, `Cloud`, `Atmosphere`, `Weather`, `Fog`, `Haze`, `Mist`, `Storm`, `Thunderstorm`, `Rain`, `Sunset`, `Horizon`, `Bird` o clases de aeronaves y otros vehículos aéreos: `Aircraft`, `Airplane`, `Airship`, `Biplane`, `Blimp`, `Cargo aircraft`, `Drone`, `Experimental aircraft`, `Fighter aircraft`, `Fixed-wing aircraft`, `Floatplane`, `Glider`, `Ground attack aircraft`, `Helicopter`, `Hot air balloon`, `Jet aircraft`, `Light aircraft`, `Military aircraft`, `Military helicopter`, `Military transport aircraft`, `Monoplane`, `Motor glider`, `Narrow-body aircraft`, `Powered hang glider`, `Propeller-driven aircraft`, `Radio-controlled aircraft`, `Radio-controlled helicopter`, `Rigid airship`, `Rocket-powered aircraft`, `Seaplane`, `Spaceplane`, `Supersonic aircraft`, `Toy airplane`, `Trijet`, `Triplane`, `Twinjet` o `Wide-body aircraft`. Los nombres se resuelven contra las descripciones oficiales de clases; si alguno falta o no es único, la ejecución aborta con un error explícito. La lista es una política semántica del proyecto, no una jerarquía completa provista por Open Images.

El set de trampas incluirá un pequeño lote independiente de fotos de aviones y helicópteros con cielo visible, propias o separadas del entrenamiento. Se medirá y documentará cuántas de esas imágenes la app rechaza como entrada no válida (`no_nube` o abstención por confianza), en formato `rechazadas/N`; no se usarán para entrenar ni ajustar el umbral. Es una limitación conocida que el modelo pueda confundirlas con una nube y aceptarlas con confianza alta si no vio ejemplos similares durante el entrenamiento; el filtro de datos no elimina ese riesgo. La app aún no se ha implementado, así que el conteo queda pendiente de ejecutar la evaluación.

Las etiquetas humanas no son exhaustivas: no tener una etiqueta de exclusión no garantiza que la imagen carezca de cielo o nubes. En una revisión visual de una muestra de 50 fotos, 2 mostraban cielo; este resultado puntual confirma que aún pueden quedar imágenes con cielo en el subconjunto, pese a los filtros. Las etiquetas adicionales reducen algunos falsos negativos previsibles (por ejemplo, cielo de fondo en puestas de sol, horizontes, aviones y aves en vuelo), pero no eliminan ese riesgo; las etiquetas ausentes no se interpretan como evidencia negativa. El script filtra en streaming las anotaciones y metadatos del split, pero descarga y conserva solo un subconjunto acotado de imágenes (hasta 1000 por defecto). Las imágenes se guardan bajo `data/`, que está ignorado por Git; `ATTRIBUTION.csv` y `CITATION.txt` se escriben separadamente bajo `docs/datasets/no_nube/open-images-v7/<split>/`, para que la atribución y las citas permanezcan versionadas junto con el repositorio. Conserva por imagen autor, título, página original, URL de licencia y cambios; limita la selección a imágenes con licencia CC BY 2.0. La cita del dataset no sustituye la atribución individual que exige CC BY. Para las imágenes provenientes de Open Images se mantiene la advertencia del proyecto de no subirlas ni publicar el modelo; esta advertencia no se aplica a CCSN.
